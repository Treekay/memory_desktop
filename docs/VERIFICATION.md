# 验证记录 · 0.1.4

实测：Windows 11 25H2、10.0.26200.0、x64、.NET Framework Release 533509。日期：2026-10-05 UTC。Windows 10 / 11 为兼容目标；Windows 10 尚未实机测试。

## 构建和测试

使用本机内置 .NET Framework x64 csc，警告等级 4、警告视为错误，无 NuGet、新增 SDK 或权限修改。`build.ps1 -Test` 通过 **138 项检查**。合成输入、报告与截图只写入 Git 忽略的 `test-results/`。

涵盖明确选择目录、有界扫描/解码、文件句柄释放、坏图和空目录、EXIF、取消与旧来源结果、暂停、设置和菜单持久化、独立淡入淡出、完整漂移碰撞、原生透明绘制、多屏全局去重。新增 3–5 秒菜单与四个档位的严格停留范围、唯一勾选、旧设置和已显示照片保留均通过。默认仍为 6–8 秒，不会因添加选项而改选。

五种视口分别十分钟验证：1920×1080、2240×1400、1080×1920、7680×2160、320×240。预留与实际边界在每一步不相交、不越界，位置覆盖九个统计区域。最长显示边至少为屏幕短边的 38%；本机主屏至少约 532 像素。没有强制网格、移动已有照片、裁切或缩小已显示照片。

默认档实测清晰停留 6.02–7.97 秒，淡入 2.8 秒、淡出 3.8 秒保持。模拟异步准备 0.6 秒的真实 PhotoSurface 请求/交付路径，600 秒中预热后的 2849 个采样帧有 1221 帧三张以上、264 帧四张明显可见；请求 142 次，照片和待解码数量保持有界。

## 两张为主的原因与前后对比

明确选择目录本次检查有 28 张可用且编码字节不重复的照片；以 3:4 竖图、4:3 横图为主，另有 9:16 竖图。该数量足够双屏各显示四张，不是去重造成的数学限制。诊断只报告数量和尺寸，释放每张原图后使用合成像素模拟，不输出文件名、指纹或照片。

旧版较大照片在随机中心位置阻挡可用空间；最小高度和留白限制使双行排布困难。每次成功交付后再等约 3–5 秒才开始下一次加载，加载准备等待还额外拉长了实际间隔。原先计数包含刚开始淡入、未来预约及接近透明的照片，不能代表用户看到的数量。

新版从可用矩形取位，并评价加入后还能否放入后续照片；尺寸随空位与比例变化，保持可读尺寸和完整漂移间距。目标缓慢变化且偏向三四张；需要更多时较早启动下一次加载，并从实际请求到交付的时间估计提前量（最大 1.2 秒、最短请求等待 0.35 秒）。仍只允许每屏一个待解码、全局一个解码队列和每屏四张活动/预约照片，独立到期点至少约 1.2 秒间隔。

“明显可见”定义为照片中央绘制不透明度至少 0.60（峰值 0.96）；不统计未来预约或初始/末尾几乎透明的照片。使用当前 28 张照片的比例和双屏几何，三个不同种子分别十分钟，预热后结果：

| 版本 | 主屏三张以上 | 主屏四张 | 副屏三张以上 | 副屏四张 |
| --- | --- | --- | --- | --- |
| 0.1.3 | 0.4–0.5% | 0% | 0.3–2.1% | 0% |
| 0.1.4 | 45.9–51.9% | 5.4–8.6% | 42.2–50.4% | 6.3–10.4% |

以上为合成模拟，并非真实桌面视觉验收；异步准备补偿另由 PhotoSurface 测试和实际绘制统计验证。代表相册的 3–5 秒档三张以上约 28.5–33.9%、四张约 1.9–3.5%；短档四张清晰时间更短，因为淡入淡出时长仍保持不变。

原生绘制器生成并检查 `composition-2.png`、`composition-3.png`、`composition-4.png`，仅含合成风景，所有计入图片达到上述不透明度门槛，尺寸有变化、位置分散、留白充足且不重叠。

## 实机运行与限制

环境含 2240×1400、150% 主屏与负 Y 坐标的 1920×1080、100% 副屏；物理边界、宿主和窗口可见已核对。此前用户确认过照片显示于桌面图标后方。本次沿用用户所选目录、梦境背景和 6–8 秒档位，暂停和登录启动均关闭；正常退出旧实例后启动新版，设置文件字节哈希核对不变，旧版保留回退。

实际绘制统计在原生 DrawNative 完成后记录对应照片中央不透明度，而不是预约计数。最终候选 PID 28844，连续约 106.9 秒绘制统计：主屏三张以上 55.7%、四张 21.3%，副屏三张以上 63.1%、四张 18.8%。主屏出现 13 段三张以上场景、7 段四张，副屏分别 19 段和 8 段；最长三张以上约 8.0 / 8.2 秒，最长四张约 4.7 / 4.6 秒。两屏窗口可见、动画时钟推进、未暂停，无错误；活动/预约与全局占用均在限制内。主/副屏平均 OnPaint 约 18.9 / 12.8ms，初次准备尖峰约 0.84 / 1.02 秒。这是原生实际绘制不透明度统计，仍不等同于人工观看桌面动画验收。当前前台为 Chrome，被动截图守卫跳过捕获，未切换窗口或操作锁屏；真实桌面主观观感仍待用户确认。

本机 raised desktop 直接创建 Progman 下的 layered child，置于图标层后方、Shell 背景层前方；经典桌面采用 WorkerW。这是非公开 Explorer 行为，系统更新可能改变层级。开发未重启 Explorer、未修改 Windows 静态壁纸、未启用登录启动。

尚未专项实测 Windows 10、Explorer 重启恢复、显示器热插拔、睡眠/锁屏恢复、HDR、第三方 Shell、虚拟桌面和远程桌面。全屏判断采用矩形近似，透明全屏可能暂停。新照片初次准备可有短暂尖峰，平均 OnPaint 或模拟占比不是稳定 FPS 或长时间内存稳定性的保证。重新编码后的视觉相同照片不做感知去重。
