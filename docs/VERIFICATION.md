# 验证记录 · 0.1.3

实测环境：Windows 11 25H2，10.0.26200.0，x64，.NET Framework Release 533509。日期：2026-10-05 UTC。Windows 10 / 11 为兼容目标；Windows 10 未实机验证。

## 构建与测试

使用本机内置 .NET Framework x64 csc，警告等级 4、警告视为错误，无 NuGet、无新增 SDK 或权限修改。`build.ps1 -Test` 通过 **128 项检查**。合成输入、报告与截图仅保存在 Git 忽略的 `test-results/`。

检查覆盖：明确选择目录、4096 路径随机采样、最长边 1600 解码、文件句柄释放、EXIF 方向、坏图与空目录、取消和来源切换序号、设置与停留菜单持久化、暂停时钟、淡入淡出包络、原生透明绘制及完整漂移碰撞。

对横屏、竖屏、超宽屏和小视口分别运行十分钟模拟。照片位置覆盖全部九个统计区域（统计分箱仅用于测试，布局不采用网格），保留原比例，最长边至少为屏幕短边的 43%。每帧验证预留区域和实际照片边界不相交；包括淡入、淡出及未来已预约照片。所有档位仍保持严格停留范围与独立到期点。

## 桌面实测与限制

此前 0.1.1 / 0.1.2 已在主屏桌面图标后方观察照片，用户明确确认看到了。环境含 2240×1400、150% 主屏与负 Y 坐标的 1920×1080、100% 副屏；两屏物理边界和挂载已核对。

本机采用 Windows 11 raised desktop 层级：直接创建 Progman 下的 layered child，置于图标层后方、Shell 背景层前方。经典桌面仍使用 WorkerW。该机制属于非公开 Explorer 行为，系统更新可能改变层级。开发未重启 Explorer、未修改 Windows 静态壁纸、未启用登录启动。

桌面呈现使用保留式 DIB/AlphaBlend；WPF 保留预览和效果准备。此前实际逐帧平均 OnPaint 主屏约 18–20ms、副屏约 12–13ms；新照片初次准备可能产生短暂尖峰。这些数据不是稳定 30 FPS 的保证，也不是新四张构图的性能结论。0.1.3 已正常退出旧实例后部署到正式目录并启动，保留旧版可执行文件供回退。连续约 106 秒日志确认双屏窗口可见、时钟推进、活动预约数每屏 2–3 张、全局占用 4–5 张，无错误；主屏平均 OnPaint 约 16.8ms、副屏约 11.6ms，初次新图尖峰约 0.85–0.99 秒。单次工作集约 224MiB、522 个句柄；这不是长时间内存稳定性的结论。用户选择目录、梦境背景、短档停留、暂停关闭和登录启动关闭均已核对，运行实例只有一个。当前前台为 Chrome，守卫截图工具跳过捕获，因此新版真实桌面观感仍待用户确认；未切换前台、未操作锁屏。

尚未专项实测 Windows 10、Explorer 重启恢复、显示器热插拔、睡眠/锁屏恢复、HDR、第三方 Shell、虚拟桌面和远程桌面。全屏覆盖判断采用矩形近似，透明全屏可能暂停。锁屏或非桌面前台时不主动操控桌面以取得截图。
